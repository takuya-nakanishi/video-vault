# video-vault 要件(たたき台 2026-08-12)

自分のインプットになる動画(YouTube・X・GFS等)を随時ダウンロードし、
Gemini等に分析させてfireへ取り込む導線の入口となるAndroidアプリ。

## 目的

1. 広告・オフライン制約なしで自分のインプット動画を視聴できる状態を作る
2. ダウンロード→文字起こし/分析→fire ingestのパイプラインの入口になる
3. Androidアプリ開発の経験値・発信ネタを得る(公開するのはパイプライン設計と汎用部分のみ。AGENTS.md公開ルール参照)

## 対象サイト(優先度は未決)

| サイト | 取得手段の見込み | 備考 |
|---|---|---|
| YouTube | yt-dlp(実績: fireの字幕取得で使用中) | 私的利用限定 |
| X | yt-dlp対応済み | 同上 |
| GFS(株式投資専門サイト) | 要調査。会員Cookie渡しでyt-dlpが通るか、DRMの有無次第 | 有料会員コンテンツ。私的利用限定・共有不可 |

## 技術選定(Claude推奨・確定前)

- **結論**: Kotlin + Jetpack Compose + youtubedl-android(yt-dlpのAndroidラッパー)
- **根拠**: ①yt-dlpが対象3サイト中2つで実績あり、サイト対応の追随をyt-dlp本体に任せられる ②同構成の先行実装Seal(GPL-3.0)が存在し設計の参照になる(コード流用はGPL感染のため不可、設計参照のみ) ③KotlinネイティブはFlutter等と比べyt-dlpバインディング・バックグラウンドDL・ストレージ周りの情報が最も厚い
- **反証条件**: iOS版も欲しくなったらFlutterを再検討(ただしiOSはサイドロード制約で自分用DLアプリの配布自体が難路)。yt-dlpがGFSに対応不能ならGFSのみ別手段(PC側スクリプト)へ分離

## パイプライン構想(将来)

```
video-vault(Android)
  └ DL → 端末 or Drive保存
       └ 文字起こし(Whisper or Gemini)→ 分析
            └ fire raw/files/ へ(transcript型・origin: external)
```

- fire側の境界(外部LLM送信ルールとの整合・逐語転記禁止の準用)は形が見えた段階で議論し、決定をfire rawへ記録する

## 決定記録(2026-08-14 Claude提案・人間の採否待ち)

旧「未決事項」5点への結論。scaffold(v0.1骨格)はこの前提で作成済み。異議があれば個別に差し戻し可。

1. **スタック**: Kotlin + Jetpack Compose + youtubedl-android で確定。根拠は上記「技術選定」のとおり。反証条件も同上
2. **保存先**: v0.1は端末ローカルのみ(アプリ専用外部ストレージ)。Drive連携は文字起こしパイプラインを繋ぐ段階で追加。根拠: Drive連携はOAuth・同期の複雑さが大きく、MVPの「広告なしで見られる」価値に不要。反証条件: PC側での文字起こし運用が月2回以上発生したら前倒し
3. **最初のターゲット**: YouTube先行(X も yt-dlp 対応済みのため同時に動く見込み)。GFSは後回し。根拠: 認証不要でyt-dlpの実績があり、初回ビルドの検証対象として不確実性が最小。反証条件: なし(GFS調査の結果に関わらずYouTube先行は変わらない)
4. **文字起こし・分析**: アプリに持たせず、PC/クラウド側の後段に分離。根拠: Whisper・Gemini呼び出しはfire側に既存資産があり、端末で動かす利点がない。アプリは「DL+視聴」に専念。反証条件: 外出先で即時に文字起こしが欲しいユースケースが実際に発生したら再考
5. **GFS技術調査**: アプリ実装前にPC側yt-dlp+ブラウザCookieで検証する(DRMありなら対象外としてPC側別手段へ分離)。調査タスクとして独立に実施

## 追加要件(2026-08-21・人間の依頼)

1. **ブックマーク**: NewsPicks・TikTokなど、よく動画を取りに行くページへ**1タップで飛べる**。
   飛び先は内蔵ブラウザ(ログインが要るサイトでもそのままCookie導線に乗れる)。
   初期値は NewsPicks / TikTok / YouTube / X。追加・削除できる
2. **ダウンロード履歴**: ダウンロード後に**どのサイトから何を取ったか**を後から見返せる。
   記録するのは URL・サイト名・動画タイトル・日時・結果(成功/失敗/中断)。
   **保存先のファイルパスは記録しない**(依頼で明示的に不要とされた)。履歴から同じURLを再実行できる
3. **UI/UXの刷新**: 最高に使いやすく、きれいに。固有の配色・アイコン(`docs/ui-ux.md`「デザインシステム」)
4. **表示名**: ランチャーに出る名前(論理名)を **ゲットVIDEO** にする。
   パッケージ名 `com.saneiclover.videovault`(物理名)は変えない(変えると別アプリ扱いになりデータが引き継がれない)
