# video-vault UI/UX仕様 v1(2026-08-16)

自分専用の動画ダウンロードアプリ。**単一の入力欄がすべての入口**という設計。

商用アプリ `apps/personal-ai` の取込UX(`../../personal-ai/docs/capture-ux.md`)と同じ思想で、
**video-vaultが先行してその設計を実地で検証する実験場**になる。ここで確かめた挙動を商用版へ持っていく。

## 設計の決定(2026-08-16)

**デザインツール(Figma・Canva)は使わない。Composeでコードを書きながらUIを確定させる。**

理由:

1. **Figma→コードの経路はReact/Web向け**に作られており、Compose(Androidネイティブ)は対象外。
   Figma Make や Dev Mode 経由の変換が高い再現度を出すという報告はいずれもWeb系スタックの話で、
   Composeでは結局手で翻訳することになる。Figmaに投じた時間がコードにならない
2. **このアプリのユーザーは1人**。デザインシステムは他人に渡すための資産であり、渡す相手がいない
3. **最も検証すべきUXがFigmaではテストできない**——日本語IME(Input Method Editor、日本語入力)の挙動。
   競合Recallは入力欄で未確定文字列が勝手に確定する不具合を抱えていた(2026-08-15実測)。
   Figmaのプロトタイプに文字を打っても、Composeの `TextField` が日本語をどう扱うかは分からない。
   **検証対象がツールの外にある以上、そのツールで作ったプロトタイプは意思決定に使えない**

デザインの規範は **Material 3**(Googleの現行デザインシステム)のコンポーネントとカラーロールに乗る。
余白・モーション・部品の振る舞いは自分で設計しない。反復はAndroid Studioの
Compose Preview と Live Edit で実機に対して行う。

## デザインシステム(2026-08-21決定)

「最高にきれいに」の依頼を受け、**色とアイコンだけは固有のものを持つ**ことにした
(それまでは壁紙追従の動的カラー)。理由は、アプリアイコンと画面の色を一致させ、
どの端末でも同じ顔にするため。実体は `ui/theme/Color.kt` と `ui/theme/Theme.kt`。

| 要素 | 決定 | 根拠 |
|---|---|---|
| 基調色 | **エレクトリック・バイオレット**(`#4F3DE8`)。primaryとアイコン背景に使う | 動画系アプリの赤・黒と被らず、一目で自分のアプリと分かる |
| 強調色 | **コーラル**(tertiary)。失敗・削除など注意を引く箇所だけ | 基調色と補色関係で、使う場所を絞るほど効く |
| 面の色 | 紫がかったニュートラル(`surfaceContainer*` 5段階) | カードの重なりを影ではなく色の段差で表す(M3の流儀) |
| 書体 | 端末のシステムフォント(日本語はNoto Sans CJK) | 日本語フォントの同梱は十数MB増える。代わりに**太さの差**で階層を作る |
| 角 | 入力欄は完全なピル(28dp)、カードは20dp、モノグラムは12dp | 入力欄を画面で最も柔らかく・大きく見せる |
| アイコン | 24dpグリッド・2dpストローク・丸端で自作(`res/drawable/ic_*.xml`) | `material-icons-extended` を入れない(APKが肥大する)。線質を揃える |
| サイトの表現 | **頭文字のモノグラム**(名前から決まる固定色) | ファビコンを取りに行かない。オフラインでも一覧が崩れない |
| アプリアイコン | 再生マーク(▶)を90°倒して矢印の頭にした「**再生ボタンでできた下向き矢印**」。白、バイオレットのグラデーション地 | 「動画を取ってくる」を一つの形で言う。Adaptive Icon(ベクタのみ・単色レイヤー付き) |
| 表示名 | **ゲットVIDEO**(`strings.xml` の `app_name`) | 物理名(パッケージ名)は変えない |

避けたもの: 絵文字をアイコン代わりに使う、左端に色帯を付けたカード、目的のないグラデーション。

### 画質の選択(2026-08-21・人間の依頼)

どの入口(候補カード・動画バッジ・⋮メニュー)からでも、ダウンロード前に**画質シート**が出る。
「オリジナル(サイトの最高画質)/ HD(1080pまで)/ SD(480pまで)」の3択で、行のタップで即開始。
前回の選択に印を付けて1タップで済むようにし、選択は `SharedPreferences` に覚える。
解像度の上限だけを変え、**フレームレートと音声はサイトの元のまま**(yt-dlp の `-f` で
`bv*[height<=N]+ba/b[height<=N]/bv*+ba/b`。上限に合う形式が無いサイトでは最高画質へ退避し、失敗にしない)。
選んだ画質は履歴に残り、行の副見出しに「YouTube · SD · 3分前」のように出る(オリジナルは表示しない)。

**Vidyard の動画では、画質の上にパスワード欄を出す**(2026-11-10。人間の「Vidyard の動画が取れない」という問いを調べ、
原因がパスワード保護だったので、Claude が判断して足した。欄の形そのものは人間の指定ではない)。
欄の名前は「パスワード(保護された動画だけ)」。保護されているかは走らせるまで分からないので、空欄のままでも始められる。
保護されていて空欄なら、結果の帯が「パスワードで保護された動画。ダウンロードを押し直し、画質の選択でパスワードを入れる」と案内する。
入力は伏せ字で、右端の「表示」で見せられる。**パスワードは保存しない**(画面の保存状態にも入れない)。
内蔵ブラウザのプレイヤーで入れたパスワードは引き継げないので、ここで入れ直す(理由は `../AGENTS.md`「Vidyard のパスワード保護」)。

### サイトのアイコン(2026-08-21変更)

ブックマーク・履歴・進捗カードのアイコンは**ファビコン**(Googleの favicon サービスから128px)。
取れたら `files/favicons/<host>.png` に置いて以後はオフラインで出す。取れないサイトは頭文字のモノグラムに退避。
それまでは「ネットワークに依存しない」を優先してモノグラムだけだったが、人間から
「YouTubeやXのアイコンが出ていない」と指摘され、一目で分かる方を取った。

### パスキー(WebAuthn)は使えない(2026-08-21・Androidの制限)

アプリ内WebViewでパスキーを使うには、Androidの仕様で **(a) サイト側が `assetlinks.json` にこのアプリを
載せる**か、**(b) ブラウザ特権(`CREDENTIAL_MANAGER_SET_ORIGIN`。システムブラウザ限定)**が要る。
どちらも第三者アプリには不可能なので、Xの2要素認証で「パスキー」を選ぶと「見つからない」で弾かれる
(2026-08-21 実機)。アプリ側は `navigator.credentials.get/create` の呼び出しを検知して
「このアプリ内ブラウザではパスキーが使えない。認証アプリ・SMS・パスワードで」と帯で案内する。
**回避策はユーザー側の設定**: Xの2要素認証に「認証アプリ(TOTP。1Passwordで生成できる)」か SMS を
追加する(パスキーは残したままでよい)。Googleでログイン → TOTP なら通る。

### ホームの構造

入力欄が空のときと、何か入っているときで**下半分が入れ替わる**。

- **空**: ブックマーク(2列のタイル)→ 最近のダウンロード(5件。「すべて見る」で履歴画面)
- **入力中**: 候補カード(第一候補は塗り、第二候補は淡い面)。ブックマークと履歴は隠す
- ダウンロード中は進捗カードが入力欄の直下に出る。結果は帯(バナー)で残り、閉じるまで消えない

### ブックマーク

- タイル1タップで内蔵ブラウザに飛ぶ。**長押しで操作シート「編集 / 削除 / 閉じる」**(2026-08-21・人間の依頼で
  「やめる/削除」の2択から変更)。「編集」は追加時と同じダイアログを登録内容入りで開き、id と並び順は保ったまま
  名前・URLを差し替える。「削除」は即実行(シートが確認の代わり)。「追加」で名前+URLを手入力
- 内蔵ブラウザの右上の栞アイコンで、今のページを出し入れできる(名前はページタイトル)
- 保存は `files/bookmarks.json`。初回だけ既定4件(NewsPicks / TikTok / YouTube / X)を入れる。
  全部消しても既定は復活しない(消したものが勝手に戻るのは不快)

### 履歴

- 1件=URL・サイト名・タイトル・開始/終了時刻・結果・エラー1行。**保存先パスは持たない**
- タイトルはyt-dlpの出力(`Destination:` / `Merging formats into`)から拾う(`domain/YtdlpOutput.kt`)
- 行をタップ→シートで「もう一度ダウンロード / ブラウザで開く / URLをコピー / 削除」。
  「もう一度」は入力欄にURLを戻すだけにしてある(第一候補を押せば走る。黙って再実行しない)
- 実行中にアプリが死んだ履歴は次回起動時に「中断」へ倒す(`HistoryLog.settleStale`)
- 保存は `files/history.json`。上限500件

Canvaはアプリ内UIには使わない(アイコン・ストア素材・紹介ページ用のツール)。
video-vaultはストア配信しないため当面出番はない。

## スコープ境界

対象は「**ログインは必要だが、DRMで保護されていない**」動画まで。

- **ログイン必須 ≠ DRM保護**。会員制サイトの動画はCookieを渡せば取得でき、私的複製の範囲に収まる
- **DRM(Digital Rights Management、デジタル著作権管理。Widevine等)で暗号化された動画は対象外**。
  技術的に困難であることに加え、日本の著作権法では**技術的保護手段の回避を伴う複製が
  私的使用のための複製の例外から外れる**。私的利用かどうかとは別の論点になる
- この線引きを先に決めておかないと「あのサイトが取れない」という話が繰り返し出てくる。
  DRM判定に該当したら**エラーではなく「対象外」として明示的に弾く**設計にする

取得物はすべて私的利用限定。第三者への共有は行わない(モノレポのAGENTS.mdの規約どおり)。

## 単一入力欄(オムニボックス)

画面上で最も大きく、最も目立つ常設要素。**FABは置かない**(入力欄と役割が二重になる)。

### 入力に応じた判定と提示

判定は**端末内で即座に**行い、入力するそばから候補が並び替わる。
ユーザーが「これはURLだからこのボタン」と考える必要をなくす。

| 入力内容 | 判定方法 | 第一候補 | 第二候補 |
|---|---|---|---|
| 空 | — | クリップボードにURLがあれば「このリンクを開く」チップを1枚 | — |
| 動画サイトのURL | URLパターン表で照合 | **ダウンロード** | ブラウザで開く |
| その他のURL | スキーム(http/https)とドメイン形式 | **ブラウザで開く** | — |
| キーワード(日本語・英語) | URLとして解釈できない | **Googleで検索**(結果は内蔵ブラウザで開く) | — |

- URLパターン表は将来サイトが増えるため**コードに直接書かず、設定として分離**する
  (商用版ではサーバー配信にするが、video-vaultはアプリ内のJSONで足りる)
- 判定に迷ったら**両方の候補を出す**。ユーザーに選ばせるのは「意図が本当に曖昧なとき」だけにする
- クリップボードは `getPrimaryClipDescription()` のみを先読みし、
  `getPrimaryClip()` は**チップをタップした後**に呼ぶ(Android 12以降の貼り付けトーストを出さないため)

### 共有シートからの受け取り

YouTubeアプリやXアプリの共有メニューからも投げ込めるようにする(実装済みのintent-filterを活用)。
共有された場合は入力欄に貼られた状態でアプリが開き、判定済みの候補が既に並んでいる状態にする。

## ダウンロードの2導線

### 導線1: 公開リンク(ログイン不要)

入力欄にURLを貼る → 「ダウンロード」を選ぶ → yt-dlp が直接取得。

### 導線2: ログインが必要なサイト・ブラウザで見つけた動画

1. 入力欄にサイトのURLを入れて「ブラウザで開く」(またはブックマークから)
2. **内蔵ブラウザ(WebView)でユーザーが普通にログインする**
3. ページ内に動画があると、**その動画の枠の右下に紫の丸いダウンロードバッジ**が上下に弾んで出る
   (2026-08-21変更。それまでは全ページ共通のフッターボタンだった)。弾む動き=「これはサイトではなく
   このアプリのボタン」の合図
4. バッジをタップ → 画質シートが**ブラウザ画面の上に**出る。アプリが **WebViewの保持するCookieを取り出し**、
   **動画そのもののURL**(ツイートのパーマリンク、`watch?v=`、埋め込みiframeのsrc等を推定。無ければページURL)と
   一緒に yt-dlp へ渡す
5. yt-dlp がCookieを使って取得する。ページURLで取れなければ `<video>` の直リンクで一度だけやり直す
6. 検出できないサイト向けに、下部バーの「⋮」→「このページのURLでダウンロード」を予備として残す

**ダウンロードを始めてもブラウザから離れない**(2026-08-25変更)。それまではバッジを押した瞬間に
ホームへ戻していたため、**見ていた動画の再生が止まり**、WebViewごと破棄されてページも読み直しになっていた。
画質シート・進捗(下部バーの上に細い行。中断もここから)・結果の帯は、すべてブラウザ画面に重ねて出す。
ダウンロード自体はForegroundServiceが走らせるので、そのまま再生を続けても、他のアプリへ移っても止まらない。

仕組み: `assets/video_badge.js` を読み込み完了時に注入。`<video>` と既知の埋め込み `<iframe>` を
`MutationObserver`+定期再走査で追い、画面固定レイヤー上のバッジを `getBoundingClientRect` に追従させる。
タップは `@JavascriptInterface`(`VideoVault.onVideoDownload`)でアプリへ。**クロスオリジンiframeの中は見えない**
(YouTube埋め込み等はiframe自体の枠に出す)。検出件数は下部バーに「動画 N件」で示す。

実装で踏んだ点(すべて2026-08-21・実機/エミュレータ):
- **`innerHTML` を使わない**。YouTube等はTrusted Types(CSP)で `innerHTML` を禁じており、使うと
  「This document requires 'TrustedHTML'」で注入が止まる。SVGは `createElementNS` で組む
- **`touchend` で発火する**。実タッチは touchend→click の順で来るが、動画プレイヤーへタッチを渡さないため
  `touchstart`/`touchend` で `stopPropagation`+`preventDefault` すると click が消える。touchendで発火し、
  直後のclickは 800ms のデバウンスで二重発火を防ぐ(NewsPicksで「バッジは出るが反応しない」の真因)
- **バッジは実 `<video>` ではなく「見えているプレイヤー枠」に付ける**。YouTubeは実 `<video>` が
  レターボックスで `top<0` にずれ、見える枠は `#movie_player` 側。要素とその先祖のうち viewport に
  最も大きく映る箱(ページ丈の大枠は除く)を選んで、その右下に置く

**動画の通信を横取りして解析する方式は採らない。** サイト側の実装が変わるたびに壊れるため。
Cookieを渡す方式なら、サイト対応の追随は yt-dlp 本体に任せられ、こちらのコードはCookieを渡すだけで済む。

## 実装で最初に確かめること

**日本語入力の挙動**。ホームの入力欄に「かれの」と打ち、
未確定文字列が勝手に確定しないこと、変換候補が正しく出ることを実機で確認する。

これは商用版 personal-ai の差別化の中核(日本語ネイティブ)を支える技術的前提であり、
**ここが破綻するならUIの技術選定そのものを見直す**必要がある。Compose の `TextField` で
問題が出る場合は `BasicTextField` や独自の入力接続を検討する。

## 実装状況(2026-08-21)

実装済み(エミュレータの煙試験で動作確認):

- **ホーム**: 単一入力欄、入力に応じた候補の出し分け、対象外サイトの明示、
  ブックマーク(タイル・追加・長押し削除)、最近のダウンロード(履歴5件)、進捗表示と中断
- **内蔵ブラウザ**: WebView。ページ内の動画バッジと、予備の⋮「このページのURLでダウンロード」。
  押すとCookieを Netscape形式に書き出して yt-dlp へ渡し、使用後に消す。右上の栞で今のページをブックマーク。
  **画質シート・進捗・結果はこの画面のまま出る**(ホームへ戻らない)
- **バックグラウンド継続**: ForegroundServiceで走らせ、進捗と結果を通知に出す。
  アプリを離れても、タスクから消しても続く。中断は通知のボタンか画面の「中断」から
- **履歴**: 全件・日付見出し・操作シート・全消去。**保存先パスは持たない**
- **保存済みファイル**: 一覧・合計容量・削除(確認あり)
- **Vidyard**(2026-11-10): 判定表に入れ、URL を貼るとダウンロードが第一候補になる。内蔵ブラウザでは
  埋め込みのプレイヤー(`play.vidyard.com` の iframe)にバッジが付く。パスワード付きの動画は画質シートの欄で受け取って解錠する
- 判定表は `app/src/main/assets/site_patterns.json`。判定・履歴・タイトル抽出・時刻表示・Vidyard の URL の
  ロジックは単体テスト35件で固定

### 仕様からの逸脱と、その理由

1. **クリップボードのチップは「URLがあれば」ではなく「テキストがあれば」出す。**
   中身を読まない(`getPrimaryClipDescription()` だけ見る)という制約と、
   「URLかどうかを判定してから出す」は両立しない。読んだ時点でAndroid 12以降の
   貼り付けトーストが出てしまう。**タップして初めて読み、その瞬間に判定して候補が並ぶ**形にした。
   ラベルも「クリップボードの内容を使う」に変えてある
2. **ダウンロード詳細画面は作らず、履歴の操作シートで代替した。** 再試行は履歴から
   (入力欄に戻す形)。再生・共有は次版
3. **設定画面はまだ無い。** 保存先・同時実行数・yt-dlp更新はいずれもv0.1では固定
4. **ダウンロード済み一覧はホームから外し、専用画面にした。** ホームに「履歴」と「ファイル」が
   並ぶと同じものが二重に見えるため。ホームは「どこから何を取ったか」(履歴)、
   ファイル画面は「容量の整理」(削除)と役割を分けた

### 実装して分かったこと

- **targetSdk 35 はedge-to-edgeが強制される。** 対応しないとステータスバーと
  ナビゲーションバーの下に中身が潜り込む(実際に潜った)。ルートに `safeDrawingPadding()` を入れて解消
- **別ウィンドウ(`window.open`)のログインに対応する。** X等の「Googleでログイン」は
  accounts.google.com を別ウィンドウに開き、認証結果を `window.opener` へ postMessage で返す。
  複数ウィンドウ非対応のWebViewだと開いた先が真っ白で戻れない(2026-08-21 実機。1つ目のx.com白画面)。
  `setSupportMultipleWindows(true)` + `onCreateWindow` で子WebViewとして開き、Cookieはプロセス共有なので
  受け渡しが成立する。子は「ログイン」オーバーレイで重ね、閉じるボタンと `window.close()` の両方で畳む。
  NewsPicksは全画面リダイレクト方式なので元々出なかった(方式の違いで再現条件が分かれる)。
- **WebViewの高さは MATCH_PARENT にする(最重要)。** WebViewの既定LayoutParams高さは WRAP_CONTENT で、
  すると CSS の初期包含ブロック(ICB)高さが**0**になり、`height:100vh` / `height:100%` が全部0に潰れる
  (幅は効くので `vw` は正常)。Xのログインは `vh` でレイアウトするため、モーダルが高さ0で真っ白のまま固まり、
  Googleログインもポップアップは出るがメイン画面が潰れていて「ログインされない」ように見えた
  (2026-08-21 実機。両方これが真因)。DevToolsで `100vh`→0px・`document.documentElement` の高さ0px を実測して特定。
  `WebView.layoutParams = MATCH_PARENT×MATCH_PARENT` で解消(`vh` が 0→747 になり、ログイン画面が全部描画される)。
  回転や `adjustResize` では直らない(ICBの高さそのものが0だったため)。**これはXに限らずvhで組む全サイトに効く**
- `adjustResize` も併せて付与(キーボード表示時のフォーム位置ずれ対策。上の根治とは別件の保険)
- **サイトのネイティブアプリ誘導はWebView内で止める。** NewsPicksのGoogleログイン後、
  コールバック画面が真っ白で止まった(2026-08-21 Pixel実機)。端末にNewsPicksアプリが入っており、
  ログイン後に `newspicks://` / `intent://` でアプリへ飛ばそうとする遷移をWebViewが開けないのが
  最有力の原因。http(s)以外のスキームは `shouldOverrideUrlLoading` で横取りし、外のアプリは開かず
  (開くとCookieが使えず本アプリの目的を果たせない)、帯で知らせて「サイトのトップへ」で復帰させる。
  遷移・エラー・JSコンソールは Logcat `VideoVaultBrowser` に出し、debugビルドはDevToolsを有効にした
  (`adb logcat -s VideoVaultBrowser:V`)。**実機で白画面が出たら、まずこのログを見る**
- **システムバーのアイコン色は自動では合わない。** ライトモードで時計や電池が白く沈んでいた
  (2026-08-21のスクリーンショットで発覚)。`enableEdgeToEdge()` を `setContent` の前で呼ぶと
  ライト/ダークに応じて切り替わる
- **入力欄の状態はFlowを挟まず同期更新にする。** 値を非同期に戻す作りにすると、
  日本語IMEの未確定文字列が確定させられる危険がある。ここは商用版の中核に関わるので構造で守る
- **エミュレータでもyt-dlpは起動する**(x86_64バイナリが同梱されている)。
  ただし日本語IMEの検証は実機でしかできない

## 決定した事項

### ダウンロード中のバックグラウンド継続 → ForegroundService(2026-08-25決定)

**WorkManagerではなくForegroundServiceを直接使う。** 判断の分かれ目は「ユーザーが今すぐ始めた、
進捗を見せる、いつでも中断できる1件の転送」かどうかで、WorkManagerが得意な
「制約付き・遅延実行・失敗したら後で再試行」とは性質が違う。依存も増やさずに済む
(`androidx.core` の `ServiceCompat` / `NotificationCompat` で足りる)。

実装の構造は `../AGENTS.md`「ダウンロードの実行」が正。要点は **実行状態と履歴の持ち主を
ViewModelから `DownloadCenter`(プロセス寿命のobject)へ移したこと**で、これにより
アプリを閉じている間に終わった分も履歴に残る。
