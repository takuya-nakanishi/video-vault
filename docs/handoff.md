## 次のアクション(優先順)

### 1. 実機へ最新ビルドを配る(ポート番号をもらうところから)

実機は `adb devices` に `adb-56251FDCQ001BB-...` として**接続済みのことがある**(2026-08-21はmDNS経由で見えていた)。
見えていなければ、人間に Pixel の 設定 > システム > 開発者向けオプション > ワイヤレスデバッグ の
ポート番号を聞いて `scripts/connect-pixel.sh <ポート>` → `scripts/deploy-device.sh`。

**実機で人に見てもらう点**(エミュレータでは確認できない):
- ランチャーの**アイコンと「ゲットVIDEO」の表示**。テーマアイコン(Android 13+の単色)も
- ダーク/ライトの両方での配色
- ブックマークタイルの**長押し削除**が指で自然か
- 履歴のシートの操作感

### 2. 【人間の操作が要る】日本語IMEの検証

入力欄に **「かれの」** と打ち、**未確定文字列が勝手に確定しないこと**・変換候補が正しく出ることを実機で見る。
今回のUI刷新で入力欄は `OutlinedTextField` → `TextField`(ピル型)に変えたが、
**値の同期更新という構造は変えていない**。それでも実機で確かめること。

- **なぜエージェントにできないか**: `adb shell input text` はIMEを経由せず直接文字を挿入するため、
  未確定状態そのものが再現しない。エミュレータの英語キーボードでも同様
- **なぜ重要か**: 商用版 `apps/personal-ai` の差別化の中核(日本語ネイティブ)を支える技術的前提。
  破綻するならUIの技術選定(Compose `TextField`)から見直す

### 3. 共有シートの実機確認

YouTubeアプリ → 共有 → ゲットVIDEO → 候補が並んだ状態で開くか。エミュレータにはYouTubeアプリが無く確認できない。

### 4. NewsPicks・TikTokの実地検証

ブックマークから飛ぶ導線はできたが、**そのサイトで実際にダウンロードが通るかは未検証**。
- TikTokは判定表(`site_patterns.json`)に `downloadable: true` で載っているので、動画URLを貼れば直接走る
- NewsPicksは判定表に無い(yt-dlpに専用extractorが無い)。内蔵ブラウザでログイン→「このページをダウンロード」の
  Cookie導線で試す。通らなければ `downloadable: false` で登録して「対象外」と明示する

### 5. 会員制サイト(GFS)のDRM有無調査

**アプリを触る前にPC側のyt-dlpで検証する**。DRM(Widevine)なら対象外として
`app/src/main/assets/site_patterns.json` に `downloadable: false` で登録して終わり。

### 6. 次版の機能(優先度はこの順)

- ForegroundServiceへの移行(いまは**画面を閉じると中断**され、1件ずつしか流せない。
  中断された履歴は次回起動時に「中断」と表示される)
- MediaStore経由で公共 `Download/` へ書き出す(いまはアプリ専用領域で他アプリから見えにくい)
- 保存済みファイルの再生・共有、設定画面

## 作業の始め方

```bash
cd ~/workspace/sc-products/apps/video-vault

# エミュレータ(自動テスト用。起動していなければ)
adb devices | grep emulator || \
  sg kvm -c "$ANDROID_HOME/emulator/emulator @medium_phone -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect" &

# 変更したら必ず: 実機へ配る前にエミュレータで通す
./scripts/smoke-test.sh                  # 全17シナリオ(数分かかる)
./scripts/smoke-test.sh --skip-download  # ネットワークを使わない範囲だけ(速い)

# 実機へ
./scripts/connect-pixel.sh <ポート> && ./scripts/deploy-device.sh
```

- **非対話シェルでは `~/.bashrc` が読まれない**。`JAVA_HOME` と `ANDROID_HOME` を明示的に渡すか、
  スクリプト経由で実行する(スクリプトは自分で設定している)
- 煙試験を長時間の前景で待たない。バックグラウンドで走らせてログを監視する。**`cd` を忘れて空振りしやすい**
- 煙試験は冒頭で `pm clear` して履歴・ブックマークを初期化する。**エミュレータ上のデータは試験のたびに消える**
- 画面の見た目を人に見せるときは `./scripts/screenshots.sh`(全画面・ライト/ダーク・ランチャーを
  `build/screenshots/` に撮る)。煙試験の直後に流すと実データ入りで撮れる。合否判定は煙試験が担う

## つまずきどころ(すべて実際に踏んだ)

詳細は `docs/dev-setup.md`「踏みやすい落とし穴」と `CLAUDE.md`「yt-dlp運用の要点」。要点だけ:

1. **YouTubeのDLが403で落ちたら、原因は3層のどれか**。エラー文に `JavaScript runtime` が
   含まれるかで切り分ける。`--js-runtimes` を自分で渡してはいけない(ライブラリの自動付与を壊す)
2. **煙試験の合格判定を緩めない**。`.ytdl`(69バイトのレジューム情報)を成果物と誤認して
   偽の合格を出したことがある
3. **`tap_text` は完全一致を優先する**。ホームに「最近のダウンロード」見出しができたため、
   部分一致だけだと「ダウンロード」ボタンの代わりに見出しを押す
4. **実機のペアリングコードはダイアログを閉じると即失効**する。コードをもらったら即座に叩く
5. **別LANからのadbはMTUで固まる**。`scripts/connect-pixel.sh` が宛先限定のMTUクランプを毎回張る
6. **エミュレータのウィンドウ表示は実用外**。人間の動作確認は実機で行うと決めてある
7. **`material-icons-core` にあるアイコンは限られる**(Add/Close/Delete/Refresh/Search/ArrowBack等)。
   それ以外は `res/drawable/ic_*.xml` に自作してある。`material-icons-extended` は入れない(APK肥大)
8. **永続化(JSONファイル)は単一スレッドで直列に書く**。保存のたびに `launch(Dispatchers.IO)` していたら
   同じ一時ファイルを取り合って古い状態が残り得る、起動時の非同期ロードが操作後の状態を上書きし得る、
   とCodexに指摘された(2026-08-21)。起動時ロードは同期、保存は `persist` dispatcher経由にしてある
9. **煙試験はビルド失敗で即終了する**。以前は `| tail -2` で終了コードが消え、古いAPKで合格し得た。
   ボタンを文言で特定するので、**同じ画面に同じ文言のボタンを2つ置かない**(ダイアログの確定は「保存」「削除」「消去」)
