# Lint — 健康診断

agent-base の雛形(`templates/skills/lint/`)から写したもの。写したあとはこのリポジトリのもので、工程を足したり書き換えたりしてよい。この skill は工程だけを決める。

- **先に読む**: `llm-wiki` skill(全リポジトリ共通の作り)と、直下の `AGENTS.md`「LLM Wiki」(このリポジトリの事情)。
  食い違ったら規約が正(規約どうしでは直下の `AGENTS.md` が優先)
- `AGENTS.md`「LLM Wiki」が追加の手順(この skill のディレクトリに置いた追加のファイル、追加の道具など)を指していれば、該当する工程の前に読む
- このリポジトリの事実(原本の置き場・読み方・章立て・コミットの先など)は `AGENTS.md`「LLM Wiki」に書く。手順そのものを変えるときは、この SKILL.md を直す

## 工程

0. **最新にする。**`git pull --rebase`。始める前の手順(worktree・ロックなど)が `AGENTS.md`「LLM Wiki」にあれば、それに従う
1. **機械で見る。**`node scripts/wiki/lint.mjs`(`AGENTS.md`「LLM Wiki」が追加の道具を指していれば、それも)
   - **道具の出力を正とし、同じ検査を手で繰り返さない。**何を見ているかは道具の頭のコメントにある
   - エラーは直す。注意(孤立したページ・未取り込みの原本・元の置き場と台帳の差など)は工程 2 の材料にする
2. **読んで見る。**機械では分からないもの
   - ページどうしの矛盾(同じ事実・数字・手順について違うことを書いている)
   - 確定した文書と食い違う記述(仕様は文書が正。Wiki の側が古いのか、文書を直すべき事実なのかを分ける)
   - 新しい要約ページで古くなった記述(`updated` が古く、後から足した要約ページと食い違うもの)。費用・規約など、時点が古くなった変わりうる事実
   - 何度も出てくるのにページが無い概念・実体
   - 関係があるのにリンクが張られていないページの組。孤立したページは、実体・概念ならリンクの欠けを疑って張る先を挙げ、
     問いへの答え・要約ページなら書き戻し漏れを疑って書き戻す先を挙げる
   - 出典の無い記述、**推測:** と付けるべきなのに付いていない記述
   - 書かないもの(`llm-wiki` skill と `AGENTS.md`「書かないもの」)が紛れていないか
   - 問いのうち、すでに Wiki に答えがあるもの・重複しているもの(`node scripts/wiki/open-questions.mjs` でページごとに出して見る)
   - 本文に「分からない」「原本に無い」「要確認」と書いてあるのに起票されていないもの
   - ページが多いときは、ディレクトリごとにサブエージェントへ並べて任せ、返ってきた指摘は本体が原文と照らして確かめる
3. **直す。**直せるものは直す(リンクを張る、矛盾を出典つきで並べる、誤りを訂正の書式で直す、index を直す、ページを作る)。
   消す・大きく書き換えるときは、先に人に見せる
4. **起票する。**人の判断・新しい原本・確かめ(確かめる先は `AGENTS.md`「問いの確かめ方」)が要るものは問いに、やれば終わるものは作業に起票する
   (書き方は `llm-wiki` skill「未解決の問い」と `questions-jobs` skill)。問いを触ったら `node scripts/wiki/open-questions.mjs --write`
5. **コミットする。**`node scripts/wiki/lint.mjs` がエラー 0 になってから、触ったファイルをパスを明示してコミットし、push する。
   コミットの先と件名の接頭辞は `AGENTS.md`「コミット」。本文は `llm-wiki` skill「履歴(git)」(直したものと、起票した問い・作業)。
   何も直さず起票もしなかったら、コミットしない

`llm-wiki/backlog/` の検討資料・作業資料は点検の対象にしない(Wiki の外)。問いの索引と項目のファイルは工程 2 で見る。

## 終わったら人に返すもの

- 直したものの一覧
- 起票した問い・作業(人の判断・新しい原本・確かめが要るもの)
